# alsayf

Модульный CLI-тулкит для информационной безопасности на Go.

## Сборка

Требуется Go 1.26.2 или новее. Дополнительные приложения, Rust и C-библиотеки
для стандартной сборки не нужны:

```sh
CGO_ENABLED=0 go build -o /tmp/alsayf .
/tmp/alsayf --help
```

Первичная сборка загружает Go-зависимости. Готовый бинарник и встроенные правила
работают без интернета.

## Модуль secrets

```sh
# Локальный файл или каталог, включая .env и другие скрытые файлы
/tmp/alsayf secrets scan ./project

# Несколько локальных источников
/tmp/alsayf secrets scan ./project ./configs/app.env

# Исключения и лимит размера файла в байтах
/tmp/alsayf secrets scan ./project \
  --exclude node_modules --exclude vendor --exclude '*.lock' \
  --max-file-size 2097152

# Машиночитаемый отчёт, значения секретов скрыты
/tmp/alsayf secrets scan ./project --format json > /tmp/secrets-report.json

# Ненулевой код завершения при обнаружении секретов, например для CI
/tmp/alsayf secrets scan ./project --fail-on-findings

# Список реально включённых встроенных правил
/tmp/alsayf secrets rules list
/tmp/alsayf secrets rules list --format json
```

Проверяется локальное содержимое файлов. Сканирование не делает сетевых запросов,
не проверяет работоспособность ключей, не отправляет телеметрию и не обновляет
правила. Нет флагов включения валидации или вывода исходных секретов.

Используются только пакеты `pkg/matcher`, `pkg/rule` и `pkg/types` Titus v1.1.33.
Это зафиксированная версия, совместимая с Go проекта. Верхнеуровневый пакет Titus,
онлайн-валидаторы, проверка доступности репозиториев и облачные клиенты
не импортируются. Включены правила категории `secret`, кроме помеченных `noisy`.
Правила идентификаторов, публичных ключей и хешей отдельно не включаются.

Отчёт содержит тип находки, идентификатор правила и координаты в локальном файле.
Значения всегда заменены на `[REDACTED]`; исходный контекст не выводится.
Сырые секреты обрабатываются в оперативной памяти, отдельное хранилище с ними
не создаётся. Отчёт выводится в stdout; путь сохранения выбирает пользователь.
Не сохраняйте отчёт внутри сканируемого каталога: при перенаправлении оболочка
создаёт файл до запуска сканера. Имена и пути исходных файлов в отчёте сохраняются.

Повторения объединяются по правилу и захваченным значениям. Идентификатор находки
вычисляется с новым случайным HMAC-ключом для каждого запуска: его нельзя
использовать как постоянный хеш для перебора коротких паролей. Между запусками
идентификаторы различаются. Текущий matcher Titus сохраняет первую позицию одного
секрета по одному правилу в каждом файле; все повторные позиции внутри этого файла
пока не перечисляются. Позиции в других файлах сохраняются.

### Обход файлов и ошибки

- Лимит по умолчанию — 1 MiB на файл. Превышающие его файлы пропускаются целиком.
- Сканируются UTF-8 файлы без нулевых байтов. Прочие кодировки и бинарные файлы
  пропускаются. Архивы и документы не распаковываются.
- Символические ссылки и специальные файлы пропускаются. Содержимое `.git`
  исключается; история коммитов в этой версии не сканируется.
- `.gitignore` автоматически не применяется. Для исключения каталогов и файлов
  используется повторяемый `--exclude`. Шаблон проверяется по имени элемента,
  пути относительно переданного корня и абсолютному пути; используется синтаксис
  Go `filepath.Match`. `*` не пересекает разделитель каталогов, `**` не имеет
  специального значения. Исключение каталога пропускает всё его поддерево.
- Повторно переданные или пересекающиеся пути не сканируются дважды.
- Предусмотренные пропуски перечислены в `skipped`. `complete: true` означает
  завершение сканирования в рамках этих правил, а не проверку каждого файла.
- Ошибки чтения, отмена и ошибки/таймауты правил отмечаются в `issues`,
  устанавливают `complete: false` и дают код завершения 1. Остальные доступные
  файлы продолжают сканироваться. При Ctrl+C проверка останавливается между
  файлами; уже запущенное сопоставление ограничено таймаутами движка.
- Успешный запуск возвращает 0. С `--fail-on-findings` наличие находок даёт 1.
  Отчёт при этом остаётся доступен в stdout, сообщение ошибки идёт в stderr.

Это поиск по шаблонам: возможны ложные срабатывания и пропуски. Найденный ключ
не считается автоматически действующим.

## Структура

```text
cmd/
  root.go                 # Сборка команд модулей
  secrets/
    command.go            # Корневая команда модуля secrets
    scan.go               # Команда сканирования и флаги
    rules.go              # Команда просмотра правил
internal/
  secrets/
    engine.go             # Адаптер локального matcher Titus и отбор правил
    scan.go               # Обход файлов, ограничения и дедупликация
    model.go              # Модели отчёта без исходных секретов
    report.go             # Текстовый и JSON-вывод
```

Новый модуль получает отдельные `cmd/<module>` и `internal/<module>`.
`cmd/root.go` только регистрирует его команды. Модуль `internal/secrets`
не зависит от Cobra, поэтому его можно использовать из будущих модулей.

## Проверка

```sh
CGO_ENABLED=0 go test ./...
go vet ./...
```

Тесты проверяют обнаружение синтетического токена, координаты UTF-8, маскирование,
дедупликацию между файлами, исключения и ограничения, неполные отчёты и CLI.
Отдельный тест запрещает сетевые пакеты, онлайн-валидаторы, scoring и `os/exec`
в графе зависимостей `internal/secrets`. Он анализирует граф через установленный
Go, не обращаясь к внешним сервисам при наличии зависимостей в кеше.

## Сторонние компоненты

Движок и правила: [Titus](https://github.com/praetorian-inc/titus/tree/v1.1.33),
включая правила Nosey Parker и Kingfisher. Лицензии и уведомления находятся
в `third_party/titus/`. CLI использует [Cobra](https://github.com/spf13/cobra).
